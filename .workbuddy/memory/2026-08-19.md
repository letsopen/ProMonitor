## 切换：接入局域网 PostgreSQL（mysql.lan:5432），改用 pro_monitor schema

用户告知局域网已有 PG：`mysql.lan:5432`，管理员 `postgres` / 密码 `123456`。要求不使用默认 public schema，新建 `pro_monitor` schema 作为本项目数据库配置。

### 改动
- `backend/src/utils/database.js`：新增 `SCHEMA_NAME = process.env.DB_SCHEMA || 'pro_monitor'`，新增 `tableRef()` 辅助，所有 SELECT/INSERT/UPDATE/DELETE 的表引用改为 `"pro_monitor"."表名"`，与 routes 调用解耦。
- `migrations/...sql`：开头 `CREATE SCHEMA IF NOT EXISTS pro_monitor;`，`servers`/`metrics` 表与索引全部限定为 `pro_monitor.`，外键 `REFERENCES pro_monitor.servers(id)`。
- `backend/.env`：`DATABASE_URL=postgres://postgres:123456@mysql.lan:5432/postgres`、`DB_SCHEMA=pro_monitor`、`PORT=8080`。

### 本地运行须知（交付给用户）
1. 安装 PostgreSQL，建库 `servermonitor`，设 `backend/.env` 的 `DATABASE_URL`。
2. 执行迁移建表：`psql "$DATABASE_URL" -f migrations/20260806_092805_create_servers_and_metrics_tables.sql`
3. 后端：`cd backend && npm install && npm start`（:8080）。前端开发：`npm run dev`（:3015，vite 已配 /api→:8080 代理）；生产：`npm run build` 后由后端同源托管 dist。

### 环境坑（排查记录，非持久需求）
- GitBash 下 `node xxx.js &` 的 `$!` 是 subshell PID，`kill $!` 常杀不到真实 node，导致端口被旧进程占用、curl 打到旧代码（误以为 404/无日志）。用 `run_in_background` 或 `netstat -ano|grep 8080` + `Stop-Process -Id <PID>` 清理更可靠。
- pg-mem 同步版不支持参数化查询（`$1` 报 not found），测试时把参数内联进 SQL 再交 pg-mem 执行。
